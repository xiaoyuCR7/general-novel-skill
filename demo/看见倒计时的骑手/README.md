# 示例书：看见倒计时的骑手

一本用本 skill 的完整流程写出来的示例连载（都市异能，番茄男频口径）。书名是临时名，
设定里标「提案，未确认」的内容都还没有定案。它的用途是让你看到一本书在这套流程下
实际长什么样：正文、章纲、设定和追踪表各放在哪，彼此怎么对得上。

## 现在有什么

| 内容 | 位置 |
|---|---|
| 已提交正文 2 章（2470 字、2348 字） | `正文/` |
| 总纲、第 1 卷卷纲、第 1–5 章章纲（第 3–5 章是未锁定的提案） | `大纲/` |
| 世界观、人物卡、文风锚、读者契约、禁用词 | `设定/` |
| 章节摘要、角色状态、伏笔台账、时间线、节奏配额 | `追踪/` |
| 每章的机器门禁结果 | `追踪/门禁/` |

两章都走了章事务：章纲锁定 → prepare → 写入 stage → 机器门禁 → 追踪变更核对正文出处 →
validate → 正文与五表一起提交。两章的门禁 blocking 都是 0。

## 值得看的几处

- **时间对得上**：第 1 章老太太头顶的读数从 17:02 一路走到 01:58，每一次读数都对应一个改变行动的
  决定；第 2 章陈默自己的数从 71:48:20 走到 70:03:11，与当晚的钟点一一对应。
- **追踪表里的事实都有出处**：第 2 章提交前，11 条追踪变更逐条核对了正文原文摘录。
- **伏笔有进有出**：`追踪/伏笔台账.md` 里 F1-03（钥匙与那袋外卖）第 1 章埋、第 2 章收。
- **章纲与成稿的偏差被记录**：见 `大纲/章纲_第002章.md` 末尾的「实际执行」。


## 这本示例说明不了什么

只有两章，证明不了几十万字之后的一致性。正文由模型按流程写成，起草、门禁与自查是同一个
执行者依次完成的，没有独立审稿人；机器门禁通过不等于文学质量。
