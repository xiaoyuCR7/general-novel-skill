# 示例

## 示例书：看见倒计时的骑手

[`看见倒计时的骑手/`](看见倒计时的骑手/) 是一本用本 skill 的完整流程写出来的示例连载（都市异能，番茄男频口径）。
书名是临时名，设定里标「提案，未确认」的内容都还没有定案。它的用途是让你看到一本书在这套流程下
实际长什么样：正文、章纲、设定和追踪表各放在哪，彼此怎么对得上。

本说明放在书籍目录之外：书籍工程根目录里出现无关的 Markdown 文件，会被恢复脚本当成未识别稿件。

### 现在有什么

| 内容 | 位置 |
|---|---|
| 已提交正文 5 章，共 11224 字（2465 / 2249 / 2190 / 2164 / 2156） | `正文/` |
| 总纲、第 1 卷卷纲、第 1–5 章章纲（均已锁定，文末有「实际执行」批注） | `大纲/` |
| 世界观、人物卡、文风锚、读者契约、禁用词 | `设定/` |
| 章节摘要、角色状态、伏笔台账、时间线、节奏配额 | `追踪/` |
| 每章的机器门禁结果 | `追踪/门禁/` |

五章都走了章事务，写完后又按一次独立审稿的意见逐章走了修订事务：章纲锁定 → 装配上下文 → prepare → 写入 stage → 机器门禁 → 追踪变更核对正文出处 →
validate → 正文与五表一起提交。五章的门禁 blocking 都是 0。

### 值得看的几处

- **读数前后对得上**：陈默头顶的数与故事里的钟点始终可以互相换算。第 2 章 01:57 是 70:03:11，
  第 3 章 08:38 是 63:21:40，多出整 24 小时后是 87:19:55，第 4 章 22:58 是 73:02:10，
  第 5 章 12:21 是 59:38:40。独立审稿人逐处验算过这九处读数，全部对得上。
- **钱对得上**：卡里 800 出头 → 到账 2000 → 房租 1000、住院费 1000 → 又是 800 出头；
  房租从欠 4500 到欠 3500，期限从礼拜四晚上改到下礼拜二。
- **追踪表里的事实都有出处**：第 2–5 章提交前，共 34 条追踪变更逐条核对了正文原文摘录。
- **伏笔有进有出**：`追踪/伏笔台账.md` 里 F1-03（钥匙与那袋外卖）第 1 章埋、第 2 章收；
  F1-02（他头顶的数）逐章推进；F1-05（一层楼的人同一分钟到点）第 5 章新埋。
- **章纲与成稿的偏差被记录**：见各章章纲末尾的「实际执行」，包括两处因节奏冷却规则改换事件类型的记录。

### 自己复现检查

在 skill 根目录运行：

```bash
python scripts/resume.py "demo/看见倒计时的骑手"
python scripts/check_text.py "demo/看见倒计时的骑手/正文/第005章.md" --gate-report
python scripts/validate_tracking.py "demo/看见倒计时的骑手"
python scripts/timeline_manager.py check "demo/看见倒计时的骑手"
python scripts/dashboard.py "demo/看见倒计时的骑手"
```

五条命令都应当通过：恢复报告为“已写完第 5 章，无欠账”，追踪格式全部合格，时间线 0 问题。

### 独立审稿查出了什么

五章写完后，交给一位没有参与写作、只读正文的审稿人冷读。数字和钱全部对得上，但它查出 1 处硬伤和 11 处应改的问题，都是起草者自查时没有发现的，例如：

- 第 1 章陈默把雨衣裹在了老太太身上，第 2、4 章雨衣却还在他自己身上；
- 第 3 章他站在监护室门口，却说得出医保卡“在您枕头边上”；
- 第 4 章说他从没见过母亲的数，同一段却写他上个月“在病房门口站了站”；
- 第 5 章电梯里有三个人在别的楼层下了，主角却断定出事的只有二十二楼；
- 第 5 章上午的收入撑不起他自己报的全天数目。

这些都已通过修订事务改掉，修订内容记在各章章纲的「实际执行」里。机器门禁对这类问题一条也没报，这也是流程里要求独立复核的原因。

审稿人还提了两条结构意见没有采纳，因为会改动已锁定的章纲：第 4 章缺少新的外部压力、是最容易流失读者的一章；写字楼的危机应当提前到第 4 章末。另有跨章重复的句式（“把……又看了一遍”一类）只清掉了一部分。

### 这本示例说明不了什么

只有五章，证明不了几十万字之后的一致性。只经过一位审稿人、一轮审稿，没有读者数据。机器门禁通过不等于文学质量。每一章初稿都低于章纲的目标字数，补过之后又在审稿中删掉了一部分硬塞的句子，现在各章在 2150–2470 字之间，低于章纲定的 2500。
