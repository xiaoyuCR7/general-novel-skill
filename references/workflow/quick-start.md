# 轻量模式（quick-start）

适用：作者想先试写、写一个片段或一两章看效果，还没有书籍工程，也不想先建追踪五表和章事务。
轻量模式不降低正文标准，只是不建工程；它交付的是草稿，不是已提交章节。

## 何时用、何时不用

| 情况 | 走哪条路 |
|---|---|
| 没有书籍工程，作者要“先写一章看看”“试个开头” | 本文件 |
| 作者明确要长篇连载、日更、已有工程目录 | `book-init.md` / `chapter-loop.md` |
| 已有工程但作者只想改一个片段的措辞 | 反 AI 编辑的片段模式或 `revision.md` |
| 轻量草稿写到第 3 章，或作者说要继续连载 | 按下文“升级为完整工程” |

已有书籍工程时不得用轻量模式绕过章事务；不确定时先问作者是试写还是正式连载。

## 五个问题

缺哪项问哪项，作者已给的不重复问；作者说“你定”的项给出提案并标「提案，未确认」：

1. 题材与平台（决定读者期待和单章字数；未指定按番茄长篇口径）。
2. 主角是谁、想要什么、被什么拦着。
3. 核心看点或金手指（一句话；超现实设定按 `references/craft/fictional-world.md`，不做现实可行性审查）。
4. 这一章要发生的一件事，以及结尾停在哪。
5. 文风参照：作者自己的样段、想要或不要的腔调。

## 流程

1. **迷你章纲**：根据回答列 3–5 个 beats，每个含触发、阻力、行动或反应、变化中的至少三项，
   并写明结尾方式（留已授权问题，或本章闭合）。交作者确认或修改；未确认不写正文。
   beats 撑不起目标字数时照常输出 `outline_underfilled` 与 `missing_beat_budget`，不注水。
2. **写草稿**：只读 `references/craft/scene-rendering.md`，按其中的“写时预防套路腔”起草。
   题材明确时可加读 `references/genres/INDEX.md` 匹配出的一张题材卡。
3. **一次机器自检**（脚本可用时；章节文件放在作者指定的任意目录）：

   ```bash
   python scripts/check_text.py "{chapter}" --gate-report
   ```

   blocking 命中按 `references/craft/anti-ai-style.md` 修一轮并复读；脚本不可用时说明未运行。
   不写门禁状态、不建 stage、不做追踪。
4. **交付**：正文 + 三行说明——这是「草稿，未入事务」；机器自检是否运行及结果；
   哪些设定是提案、尚未经作者确认。

## 轻量模式不做的事

- 不创建书籍工程、追踪五表、章事务或门禁状态文件，也不声称“已提交”“门禁通过”。
- 不替作者锁定书名、总纲、终局或最终反派；草稿里临时定的名字和设定都标为提案。
- 不因为没有工程就放宽正文约束：不新增未确认的反派、反转、支线，不把工程标签写进正文。

## 升级为完整工程

作者决定继续连载时，按 `book-init.md` 建工程，再把已写草稿按 `import-book.md` 导入：
草稿是待核对的原稿，其中的提案设定须经作者确认后才写入设定与追踪。此后每章走
`chapter-loop.md` 的章事务。连续轻量写到第 3 章仍未建工程时，主动提示一次升级的好处
（人物状态、伏笔与时间线开始需要持久记忆），由作者决定，不强制。
