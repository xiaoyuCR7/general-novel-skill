# 去AI味工程化：执行顺序与安全边界

`anti-ai-style.md` 定义什么算 AI 腔、什么该留（判定标准，权威）；本文件只管执行：
机器输出怎么读、先删还是先改、改到哪里停、怎么报告。两者冲突时以 `anti-ai-style.md`
与章事务（`workflow/chapter-loop.md`）为准。本文件不新增硬配额：没有“每段最多几个”
“必须列几条”“必须改几处”。

去 AI 味只对读感负责：让文字具体、自然、可读。不承诺任何 AI 检测器的分数，
也不为了过检测做同义词替换、打乱语序或故意写错。

## 机器输出怎么读

| 命令 | 输出 | 用途 |
|---|---|---|
| `check_text.py --gate-report` | 7 Gate 命中、blocking/advisory、AI 味分数（<20 轻 / 20–40 中 / ≥40 重） | 门禁与定位 |
| `check_text.py --deslop` | 六项统计加权分（<30 轻 / 30–60 中 / ≥60 重） | 诊断哪一维偏高 |
| `check_text.py --style-stats` | 句长、段长、对话占比等 | 对照 `设定/文风锚.md` |

两个分数口径不同，不能互相换算；都只决定先看哪段，不决定必须删多少。blocking 必须修复
或按 `anti-ai-style.md` 的真实授权精确豁免后重跑；advisory 是“机器拿不准”，按功能判断，
不为清零 advisory 而改。

`--deslop` 六项：禁用词密度、连续否定排比段数、心理告知句占比、公式化对话标签密度
（沉声道/淡淡地说，普通“说”不计）、平均段落句数、重复描写密度。

密度型 advisory 都要求成片才报，单次自然用法不报：比喻、解释链、微动作、套词、
否定对比（`不是A，是B`）、身体反应套词（指节发白/瞳孔一缩/深吸一口气）、公式化标签、
碎句号、低连接密度、一行一段占比（`one-line-paragraph-tic`）、叙述者点评（`narrator-gloss-tic`）。

## 删除优先三关

每处候选先判能否删，再考虑改写。三关全过才删：

1. **信息关**：是否承载伏笔、钩子、角色特征、情节推进、必要信息，或人物的反应/态度/
   关系变化？是 → 不删，最小改写。
2. **冗余关**：删掉后读者对当前段的理解是否受损？是 → 压缩，不全删。
3. **节奏关**：删掉后是否突兀（段尾悬空、指代断裂、因果缺环）？是 → 换更短的表达。

删改前核对锚点：

- 已在 `追踪/伏笔台账.md` 登记的内容，一律改写不删除。
- 含具体物件、数字、称谓、时间的句子可能是隐性伏笔或因果依据；拿不准就保留并列入
  报告的需复核项，不替作者决定。
- 本章后文依赖它的句子不删。
- `on_page_requirements` 的唯一正文证据不删；改写后证据功能必须仍在。

不整段删除。整段都是套话且无人物、动作、物件、时间地点时，也先做段内瘦身，保住过渡功能。

## 两遍式

**第一遍：定位功能损失，做最小修复。** 逐处回答“这句对信息、策略、关系、风险、节奏
或视角有何作用”。能改一个词不改一句，能删一句不重写一段；没有问题的句子保留原句。

**第二遍：连读复核，修副作用。** 不继续找词，只确认：

- 指代、时序、因果连接还在，非峰值叙述仍是自然句群（见 `scene-rendering.md`
  的“去 AI 味后的连接恢复”）。
- 没有用新套词替换旧套词（“仿佛”换“宛若”，“他很紧张”换“他攥紧拳头”）。
- 人物反应、态度和关系变化的功能没有被删掉。
- 作者认可的声线、长句、内心戏和标点没有被抹平。

复核没有发现问题就不改；只列确有证据的问题，不凑条数。重度章节可对最差的局部重写，
重写段落同样记入报告。

## 常见模式与最小修复

| 模式 | 先问 | 最小修复 |
|---|---|---|
| 高频套词（仿佛、不禁、一丝…） | 是修辞/限知不确定，还是回避具体描写？ | 无功能则删或直写；有功能则保留并按需加白 |
| 意义膨胀（一种难以言喻的…） | 抽象名词后面有没有具体所指？ | 直说所指；没有所指就删 |
| 通用结论、升华、预告收尾 | 这句是否重复了动作已交付的意义？ | 删，让已有动作或结果收尾；不另造意象替代 |
| 解释腔、论文式段落 | 是人物当场推断，还是叙述者替读者总结？ | 删重复总结；人物推断按精确豁免保留 |
| 对白同质、标签公式化 | 说话人的目的、所知、关系是否不同？ | 按人物目的改话的内容；冗余修饰标签改“说”或去掉 |
| 同构排比、否定对比 | 各项是否有真实区别？ | 只是换词加重则留最有力的一项 |
| 身体反应套词 | 这个反应是否改变互动或读者认知？ | 无功能则删或直写情绪；不换另一个身体动作 |

## 改过头的信号

去 AI 味最常见的失败不是改不掉，而是换成另一种腔调。出现下列情况说明改过头了，按第二遍回补：

- **电报体**：连续碎句、省主语、一句一段。“推门。屋里没人。”连排不是自然，是另一种模板。
- **外化套词**：每个情绪都换成手抖、握拳、移开视线、指节发白。
- **留白模板**：每段或每章都用一个短句、静物或环境意象收尾（“茶还热着。”）。
- **口语贴片**：机械往对白里加“那个……”“嘛”“呗”，而不是从人物目的出发改话。
- **失血**：只剩事件流水账，反应、迟疑和关系变化不见了。

示意（仅说明方向；本书 `设定/文风锚.md` 的作者认可样段优先于本例）：

```text
原稿：他沉默了很久没有说话，似乎在思考着什么。陈墨把剑横在膝上，指腹缓缓蹭过
      剑鞘的铜扣，心中百感交集。
改过头：他没说话。剑横在膝上。指节发白。
合适：陈墨把剑横在膝上，拇指一下下蹭着鞘口的铜扣，蹭到院墙外的早课都散了，
      还是没给师兄回话。
```

## 退化段：重写，不修补

`check_text.py --degradation` 报出同一句式、同一词或同一段落结构成片复读时，这一段是生成
退化，不是腔调问题。逐词修补只会留下骨架相同的文字：按章意图和场景卡重新起草该段，
事实、授权事件和 `on_page_requirements` 不变。重写计入本章修复轮数与删改比例。

## 删改上限

按 `--gate-report` 的分级取上限：轻度 ≤15%，中度 ≤25%，重度 ≤35%。

口径：删改比例 =（删除字符数 + 新增字符数）/ 原文非空白字符数，跨两遍累计。
删 200 字、加 100 字按 300 字计，不按净变化 100 字计。

达到上限的 80% 后只处理 blocking 和最影响阅读的几处；达到上限即停，剩余候选列入报告的
需复核项。删后跌破字数下限时改为局部重写，不用新废话凑字。

## 收敛与轮数

去 AI 味不另设轮数：与其他修复共享章事务的额度，blocking/P0 自动定向修复最多两轮，
仍未清零即 `gate_blocked`，不提交、不降级。换模型、团队、Beat 或会话不重置。
blocking 清零后，剩余 advisory 交人工判断，不为清零再开一轮。

## 报告

报告放在 stage 与正式工程之外的现有修订/语义记录里。正文和候选稿中不插入任何注释、
标记或 `[需复核]` 字样。报告包含：

```text
分级：{轻/中/重}（gate-report AI 味分数 {x}）
原文字符数 {N1} → 修订后 {N2}（净变化 {±%}）
累计删改比例 {x}%（上限 {15/25/35}%）
修订：{短摘录} → {改法}；功能与改/留理由
需复核：{行号/短摘录}；{为何未处理：可能是伏笔 / 已达上限 / 关键段落改错代价大}
```

净变化明显为正时检查是否在用更多字解释更少的信息；明显为负且接近上限时检查是否失血。
作者选择保留的需复核项，登记理由，避免后续章节重复提出。

## 白名单与豁免

规则见 `anti-ai-style.md` 的“词白名单与精确句式豁免”。`设定/禁用词.txt` 中以 `!` 开头的
行是本书豁免词（已由 `check_text.py` 实现），与 `.deslop-whitelist` 等效，用于世界观术语、
角色绰号和题材特需词。作者明确禁用的词不得擅自加白。

## 标准命令序列

```bash
# 0. 机器闸口：命中与分级，并落盘门禁状态
python scripts/check_text.py "{stage}/正文/第037章_标题.md" --min-chars 2000 --max-chars 3500 \
  --ledger "{stage}/追踪/伏笔台账.md" --current-chapter 37 --gate-report --gate-state

# 1. 可选：六项统计，辅助判断哪一维偏高（不生成改写候选）
python scripts/check_text.py "{stage}/正文/第037章_标题.md" --deslop

# 2. 两遍式人工/Agent 修订，只改 stage 中的候选正文

# 3. 修后重扫并刷新门禁状态；只跑 --gate-report 不会更新状态
python scripts/check_text.py "{stage}/正文/第037章_标题.md" --min-chars 2000 --max-chars 3500 \
  --ledger "{stage}/追踪/伏笔台账.md" --current-chapter 37 --gate-report --gate-state
```

以上只是诊断与门禁步骤；提交前仍须按 `workflow/chapter-loop.md` 执行 validate、真实语义
自查和 commit。脚本不可用时可人工审稿并保留草稿，但必须报告 `tool_unavailable`，
不能声称机器门禁已执行。
