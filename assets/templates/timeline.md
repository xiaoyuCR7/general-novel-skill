# 时间线

> 记故事内时间的推移，防止「三天后的约定」写了三十章还没到期、角色生日对不上这类事故。
> 只在发生明确时间信息时记录；章与章之间时间紧贴的可以不记。
> 由 timeline_manager.py 自动解析做冲突检测与可视化（见下文「机械检查」）。

## 时间锚点

> 声明绝对/基准时间参照，章节可用 `@锚点±偏移` 引用（如「@A1+3」= 穿越起点后第 3 天）。

| 编号 | 标签 | 时间表达式 |
|------|------|-----------|
| A1 | 穿越起点 | 穿越后第1天 |
| A2 | 开学典礼 | 9月1日 |

## 第 1 卷

| 章节 | 故事内时间 | 事件 | 时间标记/约定 |
|------|-----------|------|--------------|
| 第{N}章 | {如：天元历 300 年春 / 穿越后第 3 天 / @A1+3} | {一句话事件} | {如：与某人约定七日后比武 / 三个月后 / 闪回} |

## 机械检查

```bash
# 冲突检测（五类：倒退/跳跃过大/承诺到期/引用矛盾/分支交错）
python scripts/timeline_manager.py check "{书名目录}"

# 可视化（mermaid / ASCII / HTML 时间轴）
python scripts/timeline_manager.py viz "{书名目录}" --html
```
时间标记列建议：时间跳跃写「N年后/数月后」；承诺兑现写「约定已兑现」。

## 长篇下的加载与归档

写章时不会把整张表都读进上下文。默认只加载四部分：时间锚点；最近 10 章的行；约定列尚未了结的行（不管多旧）；本章章纲用「第N章」点名的旧行。其余的行留在本文件里，需要时按章号或关键词检索。

所以约定列要保持准确，它决定一行是否一直被加载：

- 约定、期限、赌约写在约定列。兑现或作废后，回到**当初那一行**补上「已兑现」「已作废」或「已取代」，它才会退出加载。
- 没有约定的行，约定列写「无」。不要把无关的说明写进约定列，否则这一行会被当成未了结的硬约束永远加载。
- 本章要回到很久以前的某个时间点时，在章纲里写出那一章的章号。

一卷写完后生成归档候选（只读，不改书籍工程）：

```bash
python scripts/timeline_manager.py archive "{书名目录}" --through-chapter {卷末章号} --output "{工程外目录}/时间线候选.md"
```

候选会把已了结的行移入「历史记录」分区，把未了结的约定集中到「未完成的约定与期限」分区，并写一行「当前时间位置」。命令会列出每条被保留的约定，请作者逐条确认仍未了结；确认后在下一章事务的 stage 里用候选替换本文件。
非顺叙或世界内时间变化在第4列写独立标记：`闪回`、`插叙`、`时间回溯`、`时间循环`、`重生`。
用中英文分号与说明分隔，例如 `时间回溯；依据：世界观第三条`。只在事件列提及，或写「没有时间回溯」，不构成标记。
明确标记的时间倒退只提示需语义核对，不自动判定正确；按本书时间规则、事件先后和人物知识复核。
未标记的倒退仍报错。命令返回码 `1` 包含警告与错误，须读具体级别；无问题返回 `0`。
